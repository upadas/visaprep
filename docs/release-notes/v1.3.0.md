## What's new

### Real file upload (no more placeholders)

Document upload now works end-to-end:

- **Click to browse or drag-and-drop** — hidden `<input type="file">` opens the OS file picker; drag-and-drop captures the dropped file directly
- **File type validation** — each document accepts only its valid types (PDF for forms, JPG/PNG for photos, all three for mixed docs); wrong type shows an inline error
- **Size validation** — files above 10 MB are rejected with a clear error message showing the actual file size
- **FileReader API** — file content is read client-side as a dataURL; nothing leaves the device
- **IndexedDB storage** — binary file data persisted to IndexedDB (`visaprep-files` database) so it survives page reloads; metadata (name, size, type, upload time) stored separately in localStorage

### Real file previews

After upload, FileCard shows:
- **Image files (JPG/PNG)** — 48×48 thumbnail of the actual uploaded image
- **PDF files** — "PDF" badge with real filename and formatted size (KB/MB)
- **Upload timestamp** — "uploaded at HH:MM" using the local time of upload

### Reset confirmation dialog

"Reset progress" now opens a confirmation modal before erasing anything:
- Title: "Reset all progress?"
- Message explains that statuses AND uploaded files will be erased
- Two actions: Cancel (safe) and "Yes, reset everything" (destructive, red)
- Confirming clears IndexedDB blobs then resets Zustand store

### Key implementation notes

- `src/lib/fileStorage.js` — lightweight IndexedDB wrapper with `saveBlob`, `loadBlob`, `removeBlob`, `clearBlobs`; all operations are async and silently degrade if IndexedDB is unavailable (in-memory still works)
- `DropZone` — resets `input.value` after each selection so the same file can be re-uploaded after remove
- `FileCard` — uses `file.type.startsWith('image/')` to decide thumbnail vs. PDF badge; `sizeBytes` formatted with KB/MB breakpoint
- `doReset` in App.jsx — awaits `clearBlobs()` before calling `resetProgress()` to ensure IndexedDB is cleared before localStorage
- Modal CSS (`.modal-overlay`, `.modal`) added to `tokens.css` — shared with SaveModal

## Upgrade notes from v1.2.0

- Existing `vp-files` localStorage entries with the old fake shape (`{ name: '...pdf', size: '1.4 MB · 8 pages', at: '...' }`) will render without errors — FileCard guards on `file.type?.startsWith('image/')` which is falsy for old entries
- IndexedDB is created on first upload; no migration needed
